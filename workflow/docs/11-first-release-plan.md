# 11 · 首发 MVP 计划与验收

更新：2026-10-04。本文件是当前首发计划入口，07 中早期阶段记录不再作为首发待办。

## 发布顺序与范围

1. Web 用于开发调试及公开试玩，完成电脑、手机、平板和横竖屏验收。
2. 同一验收版本出 Android 包，先内测，再提交选定应用商店。
3. 同一候选版本出 iOS 包，先 TestFlight，再 App Store。

首发保留 20 关、骨牌、传送门、开关与桥、最佳成绩、回放、分享和本机存档。不以 40–60 关为硬门槛；Steamworks、电视渠道、广告/IAP、第二款游戏和 MCP 均不作为首发依赖。

20 关是产品范围选择，不是审核保证。如果试玩发现内容短、重复或难度失控，优先替换薄弱关卡，再考虑扩充。应用名、价格、地区和具体 Android 商店由开发者提交前确定；未定之前不接变现 SDK。

## 关卡曲线与趣味性

| 关卡 | 玩家需要掌握的东西 | 最优步数 |
|---|---|---|
| 1–3 | 翻滚、竖立抵达、空洞与边界 | 2 / 3 / 4 |
| 4–8 | 转向、落点与路线选择 | 5 / 5 / 6 / 6 / 7 |
| 9–12 | 提前规划与姿态调整 | 7 / 8 / 8 / 9 |
| 13–15 | 传送后姿态不变，出口规划 | 9 / 10 / 12 |
| 16–18 | 先开桥再通过，行动顺序 | 14 / 16 / 16 |
| 19–20 | 桥与传送门共同参与路线 | 17 / 18 |

步数非递减，单关增加不超过 2 步。同样步数通过不同姿态、路线或规则提供新问题。步数、面积与洞密度只是难度代理，不等于玩家实际难度；试玩尤其检查 12→13、15→16 的新规则负担。

终章逐项消融：去掉桥后不可解；去掉传送门后均需 21 步。求解器可以排除不可解、错误缓存和无效机关，不能证明好玩。

生成器默认输出 `levels/generated/candidates/`，不覆盖正式关卡。候选经过质检、画面检查和人工试玩才可晋升，不用生成数量作为完成标准。

每关试玩检查：目标能否看懂；新约束是否明确；是否只增加面积却重复走法；失败是否来自可理解的选择而非误触；通关后是否愿意继续。

请 3–5 位新玩家试玩前 5 关与首次机关关，记录卡住的原因、完成时间、误操作和是否主动继续。若两人被同一规则卡住，先改教学；多关重复同一路线，先改关卡。首发前不为这些反馈接分析 SDK。

## 本轮实施

- 普通模式启动续玩未完成关卡，兼容旧存档；好友挑战不覆盖续玩位置。
- 入门和机关关短暂教学，已通关不重复；选关卡片显示关卡短标题。
- 第 1 关移除额外空洞；19、20 关补齐组合机关，保持 17、18 步。
- 失败后仍可选关；通关反馈期间重开使旧协程失效，进菜单停止自动换关。
- 选关按钮可换行、内容可滚动，按安全区与可用宽度排版。
- Web 高清画布按实际 canvas/CSS 比例缩放 UI，保证 Retina 的文字与触摸热区不减半；横屏教学避开棋盘，旋转窗口重新取景。
- 先写临时文件再替换存档；错误类型的主要字段不阻断启动。
- 游戏内隐私说明与在线政策源文件。发布后再把可访问 URL 填入商店。
- 门禁拒绝零套件、空结果和零断言；新增曲线与终章逐项必要性测试。

本次改了 19、20 关，旧开发存档中的这两关回放可能不再适用。验收使用独立的新存档，保留原存档；首发后调整正式谜题必须设计记录/回放迁移，不能只覆盖同名 JSON。

## Web 验收

`workflow/scripts/gf-release-check.sh` 运行自动门禁；加 `--web` 生成 Web 候选。需要 Godot 4.7.2 与匹配模板；不会提交或部署。

| 场景 | 验收要求 |
|---|---|
| 桌面 1280×720、1920×1080 | 棋盘完整，键盘完成、重开、选关和回放正常 |
| 手机 360×800、390×844、844×390 | HUD 与按钮不遮挡；选关能滚动到最后一关和全部功能 |
| 平板 768×1024 | 字体可读、按钮可点，旋转不丢局面 |
| Safari/iOS、Chrome/Android、桌面浏览器 | 实际加载、输入、缓存更新、剪贴板和持久化正常 |
| 首次打开与重新进入 | 胜利条件清楚，一滑一步；刷新后续玩位置与成绩保留 |
| 分享挑战 | 指定关卡与步数正确，正常续玩不被覆盖 |
| 通关、坠落、重开与选关交错 | 无卡死、旧流程切关和脚本错误 |
| 弱设备连续玩 10 分钟 | 无 WebGL context lost，操作稳定，画质不反复闪变 |

原生截图和 headless 仅证明部分布局与逻辑，真实浏览器和手机必须另验。记录验收 commit、Godot 版本、测试结果、关卡曲线与截图，上传同一份构建。

### 本轮验证记录（2026-10-04）

- Godot 4.7.2，16 个套件累计 1274 项断言通过；最终交互套件 408 项通过。动画/计时检查与导出并行时出现过 3 项失败，导出结束后独立复测通过；CI 保持串行验收。
- 20 关全部 valid、可解、无警告，最优步数和缓存一致；终章机关逐项消融通过。
- Web 导出成功；测试门禁对临时项目的零断言结果返回失败。
- Codex 内置浏览器实测加载、键盘第一关通关、自动进入第二关、刷新续玩、390×844 与 844×390 切换、滑动移动、选关滚动到底和中文隐私说明。
- 本地截图保存在 `games/puzzle-core/build/qa/`（构建产物不入 Git）；此次修改保留在工作区，未部署。iOS Safari、Android Chrome 和原生签名包尚未完成真机验收。

## 商店提交前仍需完成

| 项目 | 完成标准 |
|---|---|
| Android | 本次候选生成 AAB，核验包名、版本、签名、ABI 与 targetSdk；旧文档的历史出包不代表本次通过 |
| Google Play | 2026-08-31 起新提交需 API 36；以最终包和后台要求为准。其他商店分别复核 |
| iOS | macOS + Xcode、Team ID、签名与模板齐备；实际导出、Archive、真机和 TestFlight 实测 |
| 隐私 | 实际包无新增 SDK 或权限；游戏内与商店后台政策 URL 都可访问 |
| 素材 | 用真实截图；说明 20 关与本机存档，不承诺云存档、全球榜或系统分享面板 |
| 支持 | 确认反馈页与商店联系方式可用 |
| 提交 | 开发者完成账号、分级、隐私问卷、定价和地区，再上传验收构建 |

官方依据：[Android 目标 API](https://developer.android.com/google/play/requirements/target-sdk)、[Godot iOS 导出](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_ios.html)、[Apple 审核指南](https://developer.apple.com/cn/app-store/review/guidelines/)。提交当天复核规则。
